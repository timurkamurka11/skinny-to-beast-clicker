# Unity Project Context

## Project snapshot

- Unity: `6000.3.19f1`
- Render pipeline: URP `17.3.0`
- UI/rendering used by the character: uGUI `RectTransform`, `Image`, custom `BaseMeshEffect` deformers
- Built scene: `Assets/Scenes/SampleScene.unity`
- Gameplay room: created at runtime by `GameplayWindowController` as `LivingGameplayScene`
- Tests: Unity Test Framework `1.6.0`; Patch 4 EditMode and PlayMode assemblies live under `Assets/GameWorkPatch4/Tests`

## Character architecture relevant to Patch 4

1. `GameplayVisualStageController` builds one persistent Patch 3.5 `CharacterRig2D` resource and maps body stages to one of four skin definitions.
2. `CharacterRigController`, `CharacterSkinController`, and `CharacterAnimationDriver` own the logical selected skin, legacy skeleton, and legacy Animator readiness.
3. `Patch4RuntimeInstaller` discovers the character inside `LivingGameplayScene` and instantiates one `FatMan_Patch4_Instance` as a child of the legacy character root.
4. Patch 4 uses a generated uGUI layered rig (`Patch4CanvasPresentation`) and an Animator whose clips are built by editor scripts under `Assets/GameWorkPatch4/Editor`.
5. `Patch4LegacySignalBridge` forwards runtime character actions to `Patch4CharacterStateMachine`.
6. Production activation remains gated by `Patch4CharacterRigController` and `Patch4CharacterVisibilityGuard`; review tools temporarily show Patch 4 while leaving the legacy logical rig active.

## Ownership rules

- Logical stage selection and room-space movement: legacy gameplay controllers.
- Patch 4 clip state and bone animation: Patch 4 Animator/state machine.
- Visible Patch 4 pixels: the persistent generated layered rig; V23 full-frame sheets are calibration/reference data only.
- Room travel must have one owner. Patch 4 clips use in-place root animation; the room routine/review route moves the character root.
- A transform channel must have one writer per state. Runtime procedural helpers may own channels omitted from the corresponding Animator clip, but must not overwrite the same channel after the Animator.

## Generated assets

The following are intentionally generated by the Patch 4 editor continuation and may be absent from a clean checkout until Unity imports the project:

- `Assets/GameWorkPatch4/Resources/FatMan_Patch4.prefab`
- `Assets/GameWorkPatch4/Animations/FatMan_Patch4.controller`
- Patch 4 `.anim` clips and baked character layers

Generation entry points are `Patch4AutoContinuation`, `Patch4PrefabBuilder`, `Patch4AnimationLibraryBuilder`, and the V21/V23 finalizers. Avoid hand-editing generated YAML when the corresponding builder is authoritative.

## Verification entry points

- Repository contract check: `python3 Assets/GameWorkPatch4/CI/validate_patch4.py`
- Unity EditMode tests: `Patch4.EditModeTests`
- Unity PlayMode tests: `Patch4.PlayModeTests`
- Visual acceptance: Patch 4 animation-room review in the actual `LivingGameplayScene`, followed by manual observation of all ten states and repeated stage switching.

## Safety notes

- `CharacterRig2D.prefab` is shared by every body stage; do not apply room-instance transforms back to it.
- Patch 4 resources and animation assets are editor-generated. Change their builders/finalizers and validate a clean regeneration.
- Do not deactivate the legacy `VisualRoot` during Patch 4 review: `GameplayVisualStageController` treats that as an invalid selected skin and retries Stage 4.
- Preserve the locked readiness gate until visual review passes.
